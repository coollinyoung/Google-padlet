# 驗收紀錄

## 本次自動化驗證

執行 `npm run check` 與 `npm test`。目前包含 9 個測試案例：

| 案例 | 驗證重點 |
| --- | --- |
| 角色與來源 | 未登入拒絕、學生不可建牆、跨來源寫入拒絕、不可改他人貼文、名單限制 |
| 並行寫入 | 35 筆 HTTP 同時投稿保留、操作重放不重複、舊版本修改 409、喜歡不重複計數 |
| 審核與凍結 | 他人看不到待審內容／附件、學生不能核准、凍結阻擋所有學生寫入 |
| 牆設定 | 建牆重試重用 ID、重名衝突、舊設定版本衝突 |
| 加密與模式 | 加密 round-trip、錯金鑰拒絕、示範禁止公開監聽／production |
| Drive mock 目錄 | 根目錄與牆目錄不重複、改名保持 ID、附件重送重用 ID、無公開 ACL |
| Drive mock 版本 | 同步中的新貼文不被誤標已存 |
| Drive mock 失敗 | 失敗保留待同步版本，已刪資料夾不被空白目錄取代 |
| 背景重試 | 保存失敗狀態、短時間不反覆打 Drive API |

這些測試不涉及真實 Google 授權與網際網路上傳。尚未完成真實瀏覽器視覺／互動驗證；不能以語法或 HTTP 測試代替。

## 正式試用前手動驗收

- [ ] 教師 A 與 B 各自登入，根資料夾分別位於自己的 Drive。
- [ ] 教師同時新增兩面牆，資料與附件不混用。
- [ ] 重載頁面仍可看見所有內容。
- [ ] 改名後 Drive 同步改名，舊網址仍有效。
- [ ] 學生登入只需身分 scopes，不出現學生 Drive 授權要求。
- [ ] 不同網域／不在名單學生無法讀取牆或附件。
- [ ] 手機掃描正式 HTTPS QR Code，登入後回到原牆。
- [ ] 新增圖片與 PDF；上傳失敗重試不產生重複貼文。
- [ ] 附件失敗保留待完成稿；再次編輯補傳或純文字發布。
- [ ] 兩名學生與教師一起留言，畫面自動更新；輸入中的留言不被覆蓋。
- [ ] 開啟審核：同學無法讀取待審核附件，教師核准後才可讀。
- [ ] 凍結：學生發文、編輯、刪除、上傳、留言、喜歡全部被阻擋。
- [ ] 教師撤銷 Google 授權後，畫面顯示 Drive 同步失敗而非成功。
- [ ] 恢復授權後重試，之前未同步資料可以保存。
- [ ] Drive 資料夾移至垃圾桶時出現錯誤；還原後可繼續同步。
- [ ] 教師匯出備份，學生不能使用該端點。
- [ ] 以伺服器備份在測試環境還原，包含附件可讀性。
- [ ] 40 個獨立學生 session 的真實負載測試；記錄延遲、錯誤率與 Drive 配額。

通過上述項目再進行班級先導試用。完整 Padlet 對標仍需按 SPEC 與 ROADMAP 分版本驗收。
