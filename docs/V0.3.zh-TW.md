# v0.3.0 網址與影音

## 使用方法

1. 新增或編輯貼文。
2. 在「網址與影音連結」欄位逐行貼上完整網址，每篇最多 5 個。
3. 按「發布貼文」。可以只分享網址、不填內文；整篇不能完全空白。
4. 一般網址可直接開啟；YouTube／影音直連按「載入影片」或「載入音訊」後顯示播放器。
5. 按播放器的播放鍵開始，預設不自動播放。也可「開啟原始網址」。

| 類型 | 支援形式 |
| --- | --- |
| 一般網址 | `https://…` 或 `http://…`，顯示網域與可點擊網址 |
| YouTube | `youtube.com/watch?v=…`、`youtu.be/…`、`youtube.com/shorts/…`、`youtube.com/live/…`、`youtube.com/embed/…`；都需帶 http(s) 前綴 |
| YouTube 起始時間 | `t=90`、`t=1m30s` 或 `start=90`，上限 7 天 |
| 影片直連 | HTTPS 網址路徑以 `.mp4`、`.webm` 結尾，可帶查詢參數 |
| 音訊直連 | HTTPS 網址路徑以 `.mp3`、`.m4a`、`.ogg`、`.wav` 結尾，可帶查詢參數 |

影片直連是影音檔案網址，不是包含播放器的一般網頁。Vimeo、Facebook、Spotify 等頁面目前只顯示一般連結，不接受自行貼入 iframe/HTML。YouTube 播放清單／頻道頁也只顯示連結。實際編碼是否可播放由瀏覽器與來源伺服器決定。

修改貼文時可以增加、替換或刪除連結；空行會忽略，重複網址合併。編輯既有資料時若 API 完全未傳 links，會保留原連結；傳入空陣列才代表移除。

## 播放與同步

- 點選載入前不要求瀏覽器連接外部影音服務，不抓遠端縮圖。
- YouTube 使用 `youtube-nocookie.com` 的隱私加強模式；播放器仍是外部服務，載入時會對外連線。
- YouTube iframe 明確設定 `strict-origin-when-cross-origin` referrer policy，提供嵌入來源資訊。
- 影音播放器開啟時，一般遠端變更先顯示「停止影音並更新」，避免 SSE 重繪把影片重新載入。
- 關閉最後一個播放器會取得最新資料。自行變更版型、搜尋、留言或編輯等導致重繪的操作也可能停止播放。
- 若貼文不再可見、影音連結已變更或整面牆撤銷存取，會移除播放器，不為了播放而延後權限更新。

## 不能播放時

影片可能不允許嵌入、已刪除、需要登入、受年齡／地區限制，或學校網路封鎖外部影音。程式保留原始網址作為替代入口，不宣稱可以繞過來源限制。

外部影音可用性與真實瀏覽器播放尚待現場驗收；網址格式辨識不代表影片一定存在或可播放。直接檔案的暫時網址可能會到期。

## 資料保存

網址及解析後的播放器資訊與貼文一起寫入 SQLite、Drive `data.json`、JSON 備份，CSV 新增「網址」欄。**不會下載 YouTube 影片或外部影音檔到教師 Drive**，因此不是影音原檔備份。

待審貼文的連結只對作者及教師可見。截止、凍結、篇數限制、編輯版本衝突、回收與還原沿用既有規則。

## 安全與部署

- 後端只接受 http(s) 網址字串，不接受使用者提供的 embed URL、HTML 或 iframe。
- YouTube 以完整網域與 11 字元 video ID 辨識；相似網域不會被當成 YouTube。
- iframe CSP 僅允許 `https://www.youtube-nocookie.com`；直連 media-src 允許 HTTPS。
- 不抓遠端網頁 metadata，不代理外部網址，避免讓貼文網址成為伺服器的任意網路請求。
- 不新增 Google scope、YouTube API key 或套件依賴。
- 實際以兒童為對象部署時，管理員應依 YouTube 官方嵌入說明完成兒童導向網站的指定程序。

參考官方文件：
- https://developers.google.com/youtube/player_parameters
- https://support.google.com/youtube/answer/171780?hl=zh-Hant

## 升級

停止應用程式、備份 DATA_DIR 與金鑰後執行：

```bash
git pull --ff-only
npm ci
npm run check
npm test
npm start
```

僅本機試用時最後一步可改為 `npm run demo`。舊版沒有 links 欄位的貼文視為無網址，不需要重建或搬移資料。
