# v0.5.0：附件刪除、排序及影音上傳

## 使用方式

1. 新增或編輯貼文，在「加入附件」選擇一個檔案後儲存。每次上傳一件，可再次編輯補傳，合計最多五件。只有附件也可發布，不必另外填文字。
2. 卡片的「附件」按鈕開啟管理視窗，以 ↑／↓ 排序，或逐件刪除。每次操作立即保存。
3. 影音附件按「載入影片／音訊」後出現原生播放器，再按播放；預設不自動播放。可控制音量、暫停與跳轉，也可下載原檔。

| 類型 | 支援檔案 | 單檔上限 |
| --- | --- | --- |
| 圖片 | PNG、JPEG、WebP | 10 MB |
| 文件 | PDF | 10 MB |
| 影片 | MP4、WebM | 50 MB |
| 音訊 | MP3、M4A、WAV、OGG（Opus／Vorbis） | 50 MB |

五件是檔案附件總數；與每篇二十則網址／影音連結分開計算。系統檢查檔案容器標記，不只相信副檔名；不做轉碼、病毒掃描或完整媒體結構驗證。MP4/M4A 品牌或編碼不受支援時可改存常見格式；MOV、HEIC、Office 文件尚未支援。瀏覽器是否能播放取決於容器內的編碼；無法播放時可下載原檔。

## 權限與刪除

作者可管理自己的附件，牆主教師可管理全牆。凍結、截止及封存規則同樣適用。學生移除或調整附件後，若牆面啟用審核，貼文重新待審；上傳中的貼文維持待完成。

刪除會解除貼文關聯、釋放五件上限中的一個位置，原下載連結失效。已下載到裝置的副本無法收回。為避免誤刪 Drive 原始資料，本版不永久刪除伺服器／Drive 原檔，也尚未提供附件回收站或自動清理。沒有文字及網址的純附件貼文不能刪掉最後一件，請先加上內文，或直接把整篇貼文移至回收站。

排序修改會驗證貼文版本；若別人同時修改，請關閉後重新開啟附件管理，不覆蓋他人的更新。

## 上傳中斷與播放

貼文內容先儲存，再上傳檔案。檔案尚未完成時，貼文只有作者與教師可見。若收到錯誤，視窗保留同一檔案與重試識別碼，可按重試；此時先鎖定編輯欄位，避免混用不同內容。若要換檔，關閉後重新編輯即可。重新整理頁面後，瀏覽器不會保存選取的本機檔案，需重新選擇。

服務同時最多處理兩件檔案附件上傳，忙碌時提示重試；目前不是可續傳／分塊上傳。影音按需載入，Drive 串流經後端驗證權限並支援 Range 分段讀取。刪除播放中的附件或失去貼文權限後，後續頁面更新會移除播放器。開啟／關閉附件管理、排序或其他主動重繪可能中斷播放。

官方 Range 文件：https://developers.google.com/workspace/drive/api/guides/manage-downloads

## 更新與部署

停止伺服器，備份 data／demo-data，再執行：

```sh
git pull --ff-only
npm ci
npm start
```

尚未完成 OAuth 時使用 `npm run demo`。不需重建資料庫；舊附件保持原順序。反向代理上傳大小需至少 52 MB，部署文件已更新 Nginx 範例。伺服器上傳使用記憶體緩衝，需保留足夠 RAM；大型影音及慢速網路應另行測試代理逾時設定。

## 驗證

39 項測試通過，包含附件順序／完整 ID 清單、刪除權限與版本、審核／凍結、純音訊貼文、檔案類型／大小、上傳重試、刪除後不可存取、本機與模擬 Drive 的部分讀取，以及播放器建立／遠端刪除後重繪。實際學校 OAuth/Drive 與桌面、iPad、Android 的影音解碼／進度跳轉仍需實測。
